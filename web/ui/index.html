Markup

Account slot

A script manages <div class="site-header__account" id="account-slot">, which comes first inside .site-header__end, before the nav, and is the same on every page that has the nav. It comes first so that on a phone, where it sits beside the logo, it is also first to tab to; on a wide screen CSS order moves it after the nav. The signed-out button is in the page markup itself, so it shows with the page and never waits for a script; with sign-in off the script empties and hides the slot, and signed in it swaps the button for the signed-in state. Signed out, it holds a small secondary button with the GitHub mark (UI.icon('github')) and two labels: "Sign in with GitHub" on a wide screen, "Sign in" on a narrow one, where the CSS hides the other so a screen reader hears one. Signed in, it holds the login in bold and a Sign out link-button; "Signed in as" is .sr-only text before the login, and at phone width the login is hidden from sight too (still read out), so the row is the logo and Sign out. Neither is a primary button: the nav already has one.

Requests and settings

UI.request(method, url, body) resolves {ok, status, data} and never rejects. A body is sent as JSON, and a call with no body sends no headers: pass {} to a POST that has nothing to say but must still be JSON, such as a sign-out. UI.loadConfig() resolves {live, passcode, signin}, or null when the settings couldn't be read: signin is 'github' when people must sign in to open a room, else 'off'.

Use .container for the full page width, then one of three narrower widths: form (640px), intro (720px) or read (760px).

Toasts

New, not on the canvas

Toasts never hold controls. They ignore clicks, so put anything the person must act on in a callout or the dock. At most three show at once, and they sit just under the site header. For an update that should be heard but not shown, call UI.announce(message): it speaks through a hidden live region and shows nothing.
